# GRAVASSIST — επεξεργαστής πιστών

Τοπικό εργαλείο (ASP.NET Core MVC) για τη σχεδίαση των αρχείων `levels/*.txt`.
Ζωγραφίζεις το δωμάτιο 40x24 με το ποντίκι και το αποθηκεύεις κατευθείαν στον
φάκελο `levels/` του repo, σε μορφή που διαβάζει αυτούσια ο parser του
`tools/physics.py`.

Δουλεύει **χωρίς σύνδεση στο internet** — όλο το CSS/JS είναι inline, καμία
εξάρτηση από CDN.

> Αυτό το αρχείο είναι για **προγραμματιστές**. Για το πώς ΧΡΗΣΙΜΟΠΟΙΕΙΤΑΙ ο
> editor — χειρισμός, τύποι κελιών, πόρτες, καλωδίωση, δοκιμή, χτίσιμο —
> δες το [εγχειρίδιο](../docs/editor-manual.md).

## Εκτέλεση

Το .NET SDK **δεν είναι στο PATH**:

```bash
export PATH="$HOME/.dotnet:$PATH"
cd editor
dotnet run
```

Άνοιξε <http://localhost:5202>. (Ή με ρητό port:
`ASPNETCORE_URLS=http://localhost:5202 dotnet run`.)

Χτίσιμο μόνο: `dotnet build`

Για τη σύνδεση με Google χρειάζονται οι μεταβλητές περιβάλλοντος
`gravassistGid` και `gravassistGscrt`· χωρίς αυτές ο editor **δεν ξεκινά**.
Λεπτομέρειες στο [εγχειρίδιο §1](../docs/editor-manual.md#1-getting-in).

## Χειρισμός

Ο χειρισμός περιγράφεται στο [εγχειρίδιο](../docs/editor-manual.md#3-drawing)
και **δεν επαναλαμβάνεται εδώ**: ήταν ήδη μια φορά ξεπερασμένος (περιέγραφε
ελληνικά κουμπιά αφότου το UI έγινε αγγλικό) και δύο αντίγραφα του ίδιου
πίνακα ξαναποκλίνουν.

Οι ράμπες ζωγραφίζονται ως **τρίγωνα με τη σωστή φορά**, όχι ως γράμματα: τα
πολύγωνα βγαίνουν απευθείας από το `RAMP_TEST` του `tools/physics.py`, ώστε ο
σχεδιαστής να βλέπει τη γεωμετρία που θα δει και ο ήρωας.

Χρώματα σύμφωνα με την παλέτα του παιχνιδιού (`docs/concept-art.md` §5):
φόντο `#000080`, σώμα υλικού `#00FF00`, ακμή `#FF8000`, λευκό `#FFFFFF`.

## Μορφή αρχείου — τι εγγυάται ο editor

- Οι γραμμές σχολίων της **κεφαλής διατηρούνται αυτούσιες** σε κάθε αποθήκευση
  (και όσες τυχόν υπάρχουν μετά την πίστα).
- Κάθε γραμμή πίστας γράφεται με **ακριβώς 40 έγκυρους χαρακτήρες**, σε **24 γραμμές**.
- Τα σχόλια ξεκινούν με `;` — **όχι** με `#`, που είναι στερεό κελί.
- Πριν γραφτεί το αρχείο γίνεται επικύρωση· άκυρη πίστα **δεν αποθηκεύεται ποτέ**.
  Ελέγχεται και το αντίστροφο λάθος: γραμμή σχολίου που κατά λάθος μοιάζει με
  γραμμή πίστας (θα τη μετρούσε ο parser ως 25η γραμμή).

Επαλήθευση με τον ίδιο τον parser του παιχνιδιού:

```bash
cd /home/vasilhs/repos/GravassistCPC
python3 -c "import sys; sys.path.insert(0,'tools'); import physics; physics.load_room(); print('OK')"
```

## Πώς προσθέτω νέο τύπο κελιού

Όλοι οι τύποι ζουν σε **ένα σημείο**: τον πίνακα `TileCatalog.All` στο
[`Models/TileType.cs`](Models/TileType.cs). Η παλέτα, τα σχήματα στο πλέγμα, οι
έγκυροι χαρακτήρες του parser και οι συντομεύσεις πληκτρολογίου παράγονται όλα
από εκεί — το view και ο controller δεν χρειάζονται καμία αλλαγή.

1. Πρόσθεσε μία εγγραφή `new TileType(...)`: χαρακτήρας, id, κατηγορία, ελληνικό
   όνομα, επεξήγηση, χρώμα σώματος, χρώμα ακμής και το SVG του σχήματος.
2. Το SVG γράφεται σε σύστημα συντεταγμένων **8x8** (= ένα tile 8x8 pixel του
   CPC, με το `y` προς τα κάτω, όπως στο `physics.py`). Για τα χρώματα γράψε
   `var(--fill)` και `var(--edge)` — αντικαθίστανται κατά το render.
3. Πρόσθεσε τον **ίδιο χαρακτήρα** και στο `CHARS` του `tools/physics.py`.

Στην εκκίνηση ο editor διαβάζει το `CHARS` του `physics.py` και **προειδοποιεί
στο log** αν ο κατάλογος έχει ξεφύγει (λείπει ή περισσεύει χαρακτήρας).

## Ρυθμίσεις

Στο [`appsettings.json`](appsettings.json):

| Κλειδί | Προεπιλογή | Τι κάνει |
|---|---|---|
| `LevelsPath` | `../levels` | Ο φάκελος με τα `.txt` (σχετικά ως προς το `editor/`) |
| `PhysicsPath` | `../tools/physics.py` | Το αρχείο από το οποίο διαβάζεται το `CHARS` για τον έλεγχο συμφωνίας |

## API

| Endpoint | Τι κάνει |
|---|---|
| `GET /api/levels` | Λίστα αρχείων + η διαδρομή του φακέλου |
| `GET /api/levels/{name}` | Φόρτωση πίστας (γραμμές + κεφαλή + ουρά) |
| `GET /api/levels/new` | Άδεια πίστα με περίγραμμα (δεν γράφεται στον δίσκο) |
| `POST /api/levels` | Αποθήκευση· επικυρώνει πριν γράψει |
| `POST /api/levels/room` | Νέα αίθουσα με τον επόμενο ελεύθερο αριθμό |
| `POST /api/levels/room/copy` | Αντιγραφή αίθουσας |
| `POST /api/levels/room/move` | Αλλαγή αριθμού + ενημέρωση κάθε πόρτας που τη δείχνει |
| `POST /api/build` | Χτίσιμο του .dsk από τη δοσμένη αίθουσα |
| `GET /api/build/dsk` | Κατέβασμα της δισκέτας ΤΟΥ χρήστη |
| `/accounts/*`, `/admin` | Σύνδεση και διαχείριση λογαριασμών |

Τα ονόματα αρχείων περιορίζονται στον φάκελο πιστών (καμία διαδρομή, κανένα `..`),
και ο φάκελος είναι **ξεχωριστός ανά λογαριασμό**.
